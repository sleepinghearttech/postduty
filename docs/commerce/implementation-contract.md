# Commerce integration contract — 2026-10-16

Current owner brief supersedes older medical-only instructions: exactly two storefronts, `general` (healthcare + makers) and `christmas`. Canonical repo/engineering stays here. Existing PR7 Christmas files have been imported unchanged as starting point; no production release.

## Shared interfaces (keep stable)
- Existing Product columns remain. Add optional `commerce?: ProductCommerce` JSONB (PUBLIC editorial data only) and `creator_id?: string | null`.
- ProductCommerce: `sku?:string; category?:string; storefronts?:('general'|'christmas')[]; collections?:string[]; short_description?:string; materials?:string; tags?:string[]; media?:{url:string;type:'image'|'video';alt:string;attribution?:string}[]; variants?:{id:string;name:string;sku?:string;price:number;stock:number}[]; personalization?:{enabled:boolean;label:string;max_length:number;required:boolean}; made_to_order?:boolean; preparation_days?:number; capacity?:number; low_stock_threshold?:number; featured?:boolean; archived?:boolean; seo_title?:string; seo_description?:string; faqs?:{question:string;answer:string}[]; dimensions?:string; weight_grams?:number; shipping_method?:string`.
- Prices in Product and variants always integer PAISE. Existing create/update endpoints continue accepting top-level price in RUPEES; editor converts product.price/100. Public storefront default for legacy products = ['general'].
- Private `product_operations`: product_id PK, details JSONB holds costs, proposed price, commissions, licenses, manufacturing and creator-only instructions; never expose via public product queries. Owner editor accepts/sends `operations?: Record<string,unknown>` separately. Only API responses to authorized owner may join it.
- `src/lib/commerce-db.ts` will export `commerceTable(name:string):string`, `isCommerceSandbox():boolean`. Prefix `preview_` only when `COMMERCE_SANDBOX=true`. No host/client-derived selection. Supabase remains existing backend.
- Preview is persistent, isolated fictional records in new `preview_*` tables with RLS, not a production data copy. Production migration files are prepared only. Only root may apply staging SQL/deploy previews. No agent may alter production configuration or data.
- `src/lib/commerce-auth.ts`: `requireOwner(request?:NextRequest):Promise<boolean>` server validates existing admin cookie (preserved) or verified Google bearer/session bound to explicit owner identity. Never first-sign-in owner. For server pages use cookies(). Existing admin APIs each call same helper. Owner Google provisioning is unverified; fail closed if missing configuration.
- Product APIs: `/api/admin/create-product`, `/api/admin/update-product`, `/api/admin/upload-image` retained. create always draft. update accepts `{id, ...fields, commerce, operations, action?:'publish'|'unpublish'|'archive'|'duplicate'}`. response `{product: Product & {operations?:Record<string,unknown>}}`. Publish checks name/price/photo/storefronts/license clearance; no automatic publication. Default saved draft. API errors clear/sanitized.
- Upload API returns `{url,type}` accepts bounded JPEG/PNG/WebP/GIF and MP4/WebM; random keys, validated MIME/signature, no active SVG/HTML. Preview separate `commerce-preview-media` storage bucket.
- Products page SSR uses service role + commerceTable and owner auth, joins operations; no costs to public pages.
- `/admin/products` reusable mobile editor; `/admin/products/[id]/preview` protected saved draft preview. `/admin` overview; `/admin/research`, `/admin/analytics`, `/admin/creators`; existing orders remain.
- Existing CheckoutForm/CartContext remain base; support optional `variantId` and `personalization` on cart items and checkout body. Server validates canonical variant pricing/stocks/personalization. Storefront context passed and validated, defaults general for compatibility.
- Checkout agent owns payment endpoints + payment helpers + SQL transaction function supplement. Snapshot authoritative intent before Razorpay. Captured payment amount/order/currency verified server-side before atomic order+items+stock. Missing keys fail closed, sandbox rejects live keys. No real notifications in sandbox; no test payments counted as real revenue.
- New admin pages should state when data is fictional/test. Unknown analytics = Insufficient data. Never invent reviews/sales/delivery promises.
- Root handles deployment, integration, status, preview safety. Agents edit only assigned paths; no git commits/pushes unless asked.
